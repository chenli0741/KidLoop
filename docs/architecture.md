# KidLoop 系统架构

> 文档状态：第一版架构基线
>
> 更新日期：2026-09-07

## 1. 架构决策

KidLoop 采用 Web 优先架构。第一版使用 Capacitor 原生薄壳将移动 Web 应用封装为 iPhone App，Android 不在当前范围内。

系统只维护一套核心业务代码、权限规则、状态模型和后端 API。App 壳层不重复开发管理者、司机、家长或老师的业务页面。

## 2. 已确定技术栈

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| 运行时 | Node.js | 运行 Next.js 服务端代码、后台任务及开发工具。 |
| Web 与服务端框架 | Next.js | 实现响应式 Web 页面、服务端接口和服务端渲染能力。 |
| 开发语言 | TypeScript | 统一前端、服务端、共享类型和领域规则。 |
| 主数据库 | PostgreSQL | 保存用户、组织、学生、接送计划、行程、状态和审计等关系数据。 |

学生照片和学校 Pickup 地图等二进制文件不直接存入 PostgreSQL。文件由对象存储保存，PostgreSQL 记录文件标识、归属、类型及访问控制所需元数据。

### 2.1 数据库连接配置

- 本地开发通过 `.env.local` 中的 `DATABASE_URL` 连接 PostgreSQL。
- 部署环境通过平台的加密环境变量配置 `DATABASE_URL`。
- `DATABASE_URL` 只允许服务端读取，不得使用 `NEXT_PUBLIC_` 前缀或传递给浏览器。
- `.env.local` 已被 Git 忽略，连接字符串不得写入源码、项目文档、日志或提交记录。
- 2026-09-06 已完成一次只读连接测试，数据库连接正常。

## 3. 系统组成

### 3.1 Web 客户端

- Web 客户端基于 Next.js 和 TypeScript 实现。
- 使用响应式布局支持桌面、平板和手机。
- 根据登录用户的组织关系和角色显示管理者、司机、家长或老师工作区。
- 管理者端以桌面浏览器为主要使用方式。
- 司机、家长和老师端以移动界面为主要使用方式。
- 同一功能在浏览器和 App 内保持相同的数据及状态含义。
- Web 界面支持简体中文和英文，默认语言为中文。
- 当前语言通过 `kidloop_locale` Cookie 保存，由服务端页面和客户端交互组件共同读取。
- 业务状态在数据库中继续使用稳定的英文枚举值，仅在展示层进行本地化。

### 3.2 App 壳层

- 使用 Capacitor 8 封装移动 Web 应用。
- 生成仅支持 iPhone 的 Xcode 工程和 iOS 安装包。
- Xcode 工程、Target、Scheme 和 App 产品名统一为 `KidLoop`。
- Bundle ID 初始配置为 `com.chenli0741.kidloop`。
- iOS Deployment Target 为 iOS 15.0，`TARGETED_DEVICE_FAMILY` 只包含 iPhone。
- 加载和承载 KidLoop Web 客户端。
- 管理登录会话、应用生命周期、网络状态和安全存储。
- 向 Web 客户端提供受控的原生能力桥接。
- 壳层不得自行保存另一套业务数据或实现另一套接送状态机。

第一版可能需要的原生桥接能力：

- 相机和相册：拍摄或选择学生照片。
- Push Notification：接收行程、Pickup、Dropoff 和异常通知。
- 地图与导航：学校资料及 Pickup 示意图在 App 内预览；司机行程 stop 点通过受控原生桥接把目的地交给司机选择的 Apple Maps 或 Google Maps，进入驾车导航。
- 网络状态：识别弱网和离线状态，触发待同步队列。
- 本地安全存储：保存登录凭据或必要的设备令牌。
- 文件查看：展示学校 Pickup 地图图片或文件。

#### App 内链接跳转规范

- 所有链接跳转始终留在 KidLoop App 内，不得唤起 Safari、Chrome 或其他外部浏览器。
- 司机行程 stop 点的“开始导航”是此规则的业务例外：仅允许交给已安装的 Apple Maps 或 Google Maps 启动驾车导航；取消、地图未安装或启动失败时回到或留在 KidLoop。该入口不得退化成只有地图画面、没有路线引导的 iframe 预览。
- 站内业务页面由 App 内导航承载；外部网页、地图链接和文件预览由 App 内浏览或预览界面承载，并提供返回或关闭入口。
- 链接入口和壳层导航处理必须共同覆盖普通链接、`target="_blank"`、`window.open` 及重定向；无法在 App 内展示的内容应在 App 内提示，不得回退到外部浏览器。
- 外部页面在独立的受限 App 内浏览容器中打开，不因留在 App 内而获得业务页面的原生桥接权限或登录凭据。
- 必须在 iPhone App 中验证打开和返回流程，保留原业务页面及登录状态。本节记录已确认规范，具体实现状态须以代码和 App 验证为准。

### 3.3 后端 API

- 服务端接口基于 Next.js 和 Node.js 运行时实现。
- 为 Web 浏览器和 App 内 Web 客户端提供统一 API。
- 负责身份认证、组织数据隔离、角色权限和跨组织合作校验。
- 负责学生清单、行程、Pickup、Dropoff、交接、异常和通知等业务规则。
- 关键状态更新必须支持幂等处理，避免弱网重试产生重复记录。
- 所有状态变化和人工修改保留审计记录。

### 3.4 数据与文件存储

- PostgreSQL 保存组织、用户、学生、家长、司机、车辆、计划、行程和审计数据。
- 对象存储保存学生照片及学校 Pickup 地图等文件。
- 文件不能使用永久公开地址，访问时必须校验当前用户权限。
- 客户端缓存只保存完成当前任务所需的最小数据。

## 4. 逻辑结构

```text
Desktop / Tablet Browser
          |
Mobile Browser ---- Next.js Web App ---- Next.js Backend API ---- PostgreSQL
          |                    |                     |
iPhone Capacitor Shell -------+                     +---- Object Storage
          |
Camera / Push / Maps / Network / Secure Storage
```

## 5. 代码边界

- **共享 Web 业务层**：页面、表单、角色工作区、学生清单和状态交互。
- **共享领域层**：数据类型、验证规则、权限描述和状态定义。
- **服务端业务层**：组织隔离、授权、行程生成、冲突检查、状态流转和审计。
- **App 壳层**：设备 API、系统权限、通知注册、深度链接和安装包配置。
- **外部服务适配层**：地图、Push、邮件或短信、对象存储。

业务规则必须以服务端为最终依据。Web 客户端可以提前提示错误，但不能替代服务端权限和数据校验。

## 6. 弱网与同步

司机 Pickup 和 Dropoff 操作需要支持短时断网：

1. 客户端为每次操作生成唯一标识并写入本地待同步队列。
2. 界面明确显示“待同步”，不能提前显示为服务器已确认。
3. 网络恢复后按顺序重试。
4. 服务端按唯一标识执行幂等处理。
5. 发生数据冲突时保留本地操作，并提示司机或管理者处理。

## 7. 版本与发布要求

- Web 浏览器版和 App 版使用同一套后端 API 版本策略。
- App 内打包的 Web 代码必须与壳层桥接接口版本兼容。
- 纯 Web 修改和需要新增原生权限的修改必须区分发布路径。
- 新增相机、通知、定位等系统权限时，需要重新发布对应 App 安装包。
- 后端接口升级必须兼容仍在使用中的已发布 App 版本，或提供明确的最低版本升级机制。

## 8. 第一版不做

- 不分别开发原生 iOS 和 Android 业务界面。
- 不在 App 壳层中复制用户、学生、行程或状态数据模型。
- 不建设独立于 Web 系统的 App 后端。
- 不依赖持续 GPS 追踪实现基础 Pickup 和 Dropoff 流程。

## 9. 待选技术

以下是实现选型，不改变 Web 优先和 App 薄壳的架构决策：

- ORM 和数据库迁移工具。
- API 组织方式与接口规范。
- 对象存储和部署平台。
- Push Notification 与地图服务供应商。

## 10. iPhone 工程

- Xcode 工程：`ios/App/KidLoop.xcodeproj`
- Target：`KidLoop`
- Scheme：`KidLoop`
- App 产品：`KidLoop.app`
- 支持设备：iPhone
- 最低系统：iOS 15.0

Capacitor 同步：

```bash
npm run ios:sync
```

打开 Xcode：

```bash
npm run ios:open
```

在 iPhone 模拟器中连接本机 Next.js 开发服务：

```bash
CAPACITOR_SERVER_URL=http://127.0.0.1:3010 npm run ios:sync
```

真机开发时，将 `127.0.0.1` 替换为 Mac 在同一局域网内的地址。正式构建必须使用已部署的 HTTPS 地址：

```bash
CAPACITOR_SERVER_URL=https://your-kidloop-domain.example npm run ios:sync
```

不提供 `CAPACITOR_SERVER_URL` 时，App 使用内置的安全回退页面，不会把开发地址写入正式构建。


## 固定线路与每日执行（2026-09-07 确认）

当前流程为学校规则 → 固定多站线路 → 固定司机、车辆和学生 → 自动每日任务。学校规则只决定日历和年级接送时间；线路是跨学校的独立对象。旧的每日人工创建班次、行程流程已取消，历史执行表继续使用。

- 入口：学校规则及月历 `/schedule`，独立线路 `/routes`，管理员“今天” `/`，司机 `/driver`，家长 `/parent`。旧调度路径跳转到线路。
- `saveFixedRoute` 校验固定计划，`materializeRoutes` 在事务中按日期生成或同步执行快照。`ensureRouteTasks` 由管理员和司机的已鉴权运营读取调用，并在一次请求内去重；保存线路也同步今天和已存在的未来日期。家长首页只读取已发布快照，不执行全线路生成事务。
- 当前是保存及运营读取驱动的自动生成，不依赖定时任务，不预先生成全部学期记录。数据库唯一键与事务锁保证重复请求不产生重复线路任务；家长在任务生成前仍可提交日期安排。
- 原司机操作事实优先于后续配置：已执行任务不重写，未执行任务可应用司机变更。跨学校假期只排除受影响学生。容量及资源冲突会在今日页提示。
- 学校接送时间可带入站点作为参考，尚未接入地图行车耗时计算。AI 解析文字或校历并批量写入规则仍属后续能力；不得将需求讨论当作已存在的接口。
- 照片上传已使用私有 Vercel Blob 和授权读取接口，iPhone 通过 Capacitor Camera 选图或拍照；不复用参考项目的公开存储权限。

完整的界面、状态、角色及未实现范围见 [已确认需求](confirmed-requirements.md)。

## 自动名单、共享批次与试算

业务要求以 [线路与每日接送核对](route-planning.md) 为准。学生的学校及课外班关联是唯一资料来源，线路保存站点顺序、时间、资源与名单排除例外，不保存可手改的学生上下车映射。

`automatic-roster.ts` 按学校、年级放学批次和后续课外班推导站点对应；`school_pickup_batches` 统一保存学校、放学时段、星期的共享属性及整拨排除名单。参与线路自然匹配，没有主线路与伙伴线路。

`schedule-trial.ts` 是正式生成和预检共用的纯计算入口，处理校历、请假、按段容量、固定/共享车辆分配、遗漏及资源冲突。`schedule-trial-data.ts` 批量读取周/月数据，按日期内容版本保存摘要，不生成正式车次；未确定的容量结果明确需要核对。配置和需求变化使相应内容版本失效。

`schedule-materialize.ts` 在事务与统一锁内写入当日车次及唯一学生执行记录。司机操作仍通过服务端权限、共享并发和容量校验；完成整条行程后状态只读。运行中修改配置不自动改变已开始的接送。

日历摘要和所选日详情使用独立 Suspense 边界；司机未来日程只读试算。界面不传每个孩子的重复地点、地址或完整资料。

### 移动端视口与固定导航

头部、底部导航与内容区共享固定 App 容器。移动端容器以 `visualViewport.height` / `offsetTop` 跟随键盘和 iOS 视口平移，文档本身不滚动，仅 `.app-main` 可滚动。底部模块切换只重置该内容区并释放表单焦点，关闭移动端默认页面滚动定位。原生壳使用 `ios.contentInset: never`，由 CSS `env(safe-area-inset-*)` 统一提供安全区；此配置变更须重新安装原生构建。

## 独立机构运营（2026-09-15）

本期组织范围以 [独立机构运营](multi-tenancy.md) 为准：租户仅指独立接送服务商，学校与课外班仍是内部资料；暂不实现组织协作。统一登录身份与机构成员身份分离。当前工作区改为完整公司资料与负责人账号一起注册，其他工作人员、司机与家长通过公司邮件邀请激活或绑定已有账号，不再公开申请加入。邀请制迁移 056 已完成，本轮未做功能测试。登录会话只选择一个机构，接受邀请不切换已选机构。最新工作区改为各公司独立授权 Gmail；平台仅配置 OAuth client 和令牌加密密钥，参见 [通用邮箱模块](connected-mail.md)。该模块通过宿主适配器验证公司管理权限，通用代码不依赖接送业务。

业务数据库访问通过 `db.ts` 建立可信机构上下文，在事务内切换为 `kidloop_runtime` 非所有者角色；RLS、组合外键和按机构唯一约束共同隔离。身份与机构生命周期单独使用 `identity-db.ts`，不能用于普通业务查询。现有真实记录迁入默认机构并保留全部原始事实，部署必须与数据库迁移协调切换。已于 2026-09-15 完成生产迁移及新版应用同步切换，首个机构承接全部原业务数据。

## 品牌与界面术语（2026-09-17）

顶部品牌栏读取登录上下文中的 `tenantName`，来源为公司资料 `tenants.name`。首个公司已更名为 KidLoop Rides Service；这不是所有租户共用的固定公司名称。产品名称仍为 KidLoop。

接送行程的英文展示统一为 Ride / Rides，中文为「行程」；技术层的 `trips`、`Trip`、API 与路径保持原名。司机日期入口由 `DriverDatePicker` 提供，日历按钮打开原生 HTML dialog，确认后通过 Next.js 站内导航切换，取消不导航；两页不再渲染重复 PageHeader。iPhone 实机交互尚待验收。
