# 线路与每日接送核对

更新：2026-09-09。本文是当前确认的业务要求；实现验收另列，不将设计当作已交付。

## 角色和资料

负责司机、车辆和行程安排的组织统一称为「接送方」。孩子关联学校与目标课外班，学校和课外班维护自身地点资料。孩子已有这两个关联，不新增上下车地址字段。

学校日历维护学期内的正式日程：上课、放假、家长会周及其他已知安排。日程按日期或日期范围保存，年级当天的实际放学时间直接属于日程；临时发生的停课也使用同一日历结构追加。“提前放学”只是与常规时间比较后的结果，不是日历类型或排班规则。孩子当天属于哪拨接送由日历和常规规则共同决定；12:30 放学的 K 班不能因已经放学就加入 14:30 的接送。

学校、司机、车辆、学生或线路的特殊情况只能来自数据，不能在排班代码中按名称、星期或日期写分支。特例数据必须能显示日期范围、适用对象和原因。学校日期／年级日程、学生请假、临时线路、重新排班请求和司机不可用均已数据化。司机不可用支持单日或日期范围、范围内指定星期、全天或部分时段和原因；试算、正式生成、自动加开与重新排班统一读取，不能把某位司机的某天安排写成隐藏规则。

## 线路设置

先确定开始时间，再依次选择学校、课外班站点，安排日期、星期、司机和车辆。可以学校→学校→课外班，也可以学校→课外班→学校→课外班。

2026-09-14 确认的冲突处理要求：发生司机时间冲突时，按管理者确认的优先线路保留司机安排，另一条线路暂留司机空缺、等待替换，不能让冲突导致该司机所有行程都无法生成。本次陈优先执行 McAuliffe → … → Morningstar San Jose；Cumberland → Ellis → Little Tree Sunnyvale 清空司机并保留为未启用线路，待补司机后再启用。待安排学生继续显示核对异常，不代表已有接送保障。当前通过人工确认线路优先级处理，尚未实现自动优先级分配。

### 司机接送时间条件

司机新增和编辑支持「最早可接放学时间」，留空表示不限；使用洛杉矶当地时间，包含所选时刻。按每名应接学生当天实际放学时间判断，包括学校日历与年级特殊放学时间，不能把提前放学学生延后接送来绕过条件。整条线路出现不满足条件的接送时，该日期保留线路配置；部分孩子因指定日期提前放学时，按下文拆出短途并尝试其他司机，正常行程保留，无法安排的部分提示待安排；已执行任务保留原记录。其他符合条件的线路照常安排。周/月试算、日常行程生成和重新排班均应用这一条件，修改条件后重新核对已生成的今天及未来行程。

2026-09-24 校正确认：杨最早可接放学时间为 13:00，固定跑 Cumberland → Cherry Chase → Little Tree Sunnyvale；Lina 一直固定跑 Cumberland → Ellis → Little Tree Sunnyvale。星期五两条线均从 Cumberland 12:45 开始并共享该校批次；Cherry Chase 线因杨不符合 12:45 条件，由系统在不冲突且可衔接的司机中自动选择陈替补，Ellis 线仍由 Lina 执行。陈完成 13:03 的 Cherry Chase 线后继续 14:30 McAuliffe 线路。该结果由固定线路、司机时间条件和当天实际时间自然生成，不建立人工日期特例；真实日期特例必须明确显示日期范围和原因。

系统按学校站点和对应放学时段自动带出学生，并自动对应上下车站。管理员不逐个学生填写时间、不选择上下车地点、不重复维护正向名单。孩子关联的学校和课外班不在每个学生下重复显示，更不显示地址。名单只有勾选框、姓名和年级，默认全选；名单标题显示整条线路已选人数，各学校接送批次标题显示本批次已选人数，勾选时即时更新，保存后线路名称旁显示已选总人数；取消勾选保留该行，表示另有安排，不表示删除或缺席。

Cumberland→Cherry Chase→小树苗线路中，Cumberland 的孩子在 Cumberland 上车、小树苗下车，途经 Cherry Chase 接人不改变孩子的资料。容量按各路段实际同时在车人数计算，名单总人数不是车辆同时占座数。

## 学校接送批次与共享

共享属于某个学校、对应放学时段的这拨接送，按日期和星期适用，不属于孩子或某条主线路。把该拨设为共享后，其他参与这拨接送的线路自动显示同一名单和共享状态；没有主线路、伙伴线路、双份名单或逐个孩子共享开关。

共享名单中的个别学生可以取消勾选，另行接送。共享名单排除对该拨接送一致生效。临时单独接送按该临时线路勾选接管学生，可接回共享批次中另行安排的孩子；不会修改原学校批次的共享名单或带走其他学生。固定分车是另外一种安排：自动列出全部候选后，通过各车勾选保留固定名单。

车辆实际接走孩子后，其他司机看到已接走及接走车辆。唯一学生执行记录和原操作历史保留，事务防止重复接走。固定乘客预留座位，共享候选只在实际接走后占该车座位。整个行程完成后孩子状态只读；行程按 Stop 顺序推进，不能跳站。

## 每日接送核对

不在取消勾选时强制检查去向。接送方安排完成后按周或月试算，按学校核对当天全部应接孩子，包括被排除后另行安排的孩子。检查漏安排、非共享重复安排、容量不足、司机车辆不可用或时间冲突、资料或放学规则缺失；按当天请假、每周不接和停课排除无需服务的孩子。共享候选出现在参与线路上不算重复。

管理端当天概览提示异常；周/月日历在异常日期显示标记，点入查看学校、孩子及原因。安排预检不等于已经接走，执行状态另行记录。

## 试算与性能

未来无须先创建正式车次才能检查。试算和正式生成使用同一套匹配、时间、容量及冲突规则。批量读取期间数据、批量计算，仅返回每天有无行程、停课与异常摘要；详情按所选日期加载。不得为查看月历逐日写入正式车次。

保存摘要并对资料、校历、线路、资源、请假变化失效，只重算受影响日期。未检查、检查中或旧结果明确标示，不当作正常。周/月同时区分过去、今天和未来，选中样式与这些含义独立。

## 数据迁移与验收

用现有学校、学生、课外班关联和真实放学规则迁移。旧手选名单迁为必要的排除例外，旧线路配对迁为学校接送批次共享。删除冲突的旧配置入口及其权威数据来源，不能让两套规则同时生效。每日车次只能通过可见线路配置正常生成。

本次用户明确授权清空全部旧运行数据：旧车次、排班、学生执行状态及操作历史删除后重建。学生、学校、课外班、家长关系、照片、司机车辆、校历和有效请假作为输入保留。上线后的日常配置修改仍保护正在执行的行程。未安排、容量不足等真实问题显示出来，不能编造司机、学生或安排消除提示。

验收覆盖自动名单与早放批次、途经学校、取消后保留行、多车共享及并发、按段容量、未安排校验、周/月概要与详情一致、变更后重新核对、完成后只读、中英文及桌面/iPhone 布局。性能需实测，区分本机测量与线上结果。

## 常跑司机权重与部分年级提前接送（2026-09-14）

司机熟悉度自动从实际执行记录计算，已发布但未接送的车次、日历试算和重复生成都不计分。读取目标日期前 180 天的执行记录，每趟同线路 10 分、仅同学校 2 分（不重复叠加），每 60 天权重减半。新司机无历史时按固定线路已绑定司机优先，加 5 分；车辆同等可行时优先原车。司机状态、最早可接放学时间、车辆可用性、座位数、已有任务和前后转场时间都是硬条件，权重不能突破。固定线路的明确绑定不因学习悄悄改写；权重用于自动加开及重新排班的人选排序，管理员在线路页可查看各司机的历史权重。

某日期或日期范围中，K 等部分年级比通常时间提前时，仅将这些孩子从正常名单拆出，按学校、实际放学时间和目的地分组，加开学校至课外班的短途。其余学校和年级仍按原时间与线路执行，不整条线路提前，也不让早放学生等待到正常时段。日期范围结束后回到常规计划；本需求中的 K 12:45 是功能测试例子，不因此改写真实校历。

加开任务先考虑常跑司机；优先保证正常线路不被挤掉。司机和车辆均须能从上一趟终点赶到加开起点，完成后赶到下一趟起点；转场和直达路程只采用已配置的有向行驶时间，可以组合已知路段，不凭空估计缺失时间。当前每个学校/时间/目的地组安排一辆能容纳该组的车；若没有足够座位、缺少行驶时间、资源不可用或有冲突，保留正常线路，明确显示加开未安排及受影响学生，不声称找到可行方案。多个加开组采用有上限的联合搜索，先最大化覆盖学生数，再按熟悉度排序。

同一共享批次的提前学生合并为一次接送；非共享重复归属仍提示核对。家长请假、每周不接、已有人工临时接送排除出自动加开。已开始的接送保留原司机和学生执行记录，不能重新领取；已由加开任务接走的孩子不再回到正常名单，正常行程其余孩子继续执行。

加开车次有独立、稳定的生成标识与来源线路，重复生成复用同一车次和学生任务，不创建临时固定线路模板。实际车次记录来源线路，因此今后真实执行加开也会增加司机对来源线路的熟悉度。周/月预览使用同一计算逻辑，预览不写正式行程；仍按既有「保存学校规则 → 生成排班」流程发布。

## 每位司机的持久化偏好（2026-09-14）

资料 → 车队 → 添加/编辑司机提供可保存的时间与学校设置，不按姓名写特例。最早、最晚可接放学时间均可留空，边界包含所选时刻，以孩子实际放学时间判断（不是整趟结束时间）。学校模式为 NONE（不限）、PREFER（优先接，可支援其他学校）、ONLY（只接所选学校）；学校可多选并通过外键关联，不绑定某条固定线路。ONLY 要求本趟实际接送孩子的全部学校在集合内，送达课外班不属于学校筛选。

自动加开及重新排班先满足时间、学校硬限制、司机车辆状态和衔接条件，尽量覆盖学生；在可行方案中明确学校偏好优先于历史熟悉度，避免偶尔支援把长期偏好改掉。PREFER 不禁止其他学校任务。已有固定线路明确绑定继续保留，但与 ONLY 或时间条件冲突时提示需改派，不能强行生成。已执行行程保持原记录。

时间与模式存于 drivers，所选学校存于 driver_school_preferences；新增与编辑使用事务、服务端校验，编辑沿用版本检查。司机卡片显示保存值，排班快照/预览缓存包含偏好。现有司机默认不限学校，已有最早时间保留；用户举例不自动变为具体司机的硬限制。
