# 自然语言排班调整：实现与验证记录

日期：2026-09-08。开发代码已落地，尚未部署；本地真实 AI 调用配置未就绪。

## 入口和行为

管理员在线路页选择“智能调整接送安排”，进入 `/routes/adjust`。描述学校日历日程变化、司机或车辆不可用，以及需要保留的线路；系统生成候选，核对前后安排并确认后应用。语音录音最长 60 秒，转写文字可修改，再进入同一流程。

不包含班级需求，不增加业务规则配置。界面保留中英文文案，沿用当前全局语言设置；默认语言及账号对应的语言切换限制由全局功能控制，本功能不覆盖这些设置。

## 已实现

- OpenAI Responses API 结构化解析；读取学校、人车、线路的精简目录，缺项追问，拒绝未知资源、无效年级和日期。没有将排班搜索交给模型。
- 每次最多 14 天、单日最多 30 条参与搜索的线路；有限搜索最多 20,000 个节点、约 2.5 秒，返回最多 3 个候选。这些是技术保护上限，不是新增运营规则。
- 共享 `route-plan.ts` 的日期资格查询、站点时间推导及分段容量函数；每日生成器同步使用，回归保留原有规则。
- 尝试原线路调时、人车分配、按上下车点及已有时间拆分学生组，以及有已存模板方向和时间间隔依据的跨校合并。无站间依据时不编造车程。
- 展示方案时间线、原安排和新安排、学生名单、影响次数、锁定条件、资源约束及用量。保留锁定或已执行任务作为边界。
- 草案和用量独立保存；试算不创建正式行程，不写校历或固定线路。相同请求追加条件形成新版本。
- 确认时重新读取当前数据和运行校验；检查校历、名单、资源、实际执行及新增冲突记录。旧版本、变更后的快照和其他用户记录不能提交。
- 整组事务保存学校日历日程和单日临时线路，原固定名单不变。移动学生任务记录以保留 ID、家长请假及状态历史。
- 原学校日历日程跨多日时，仅切分并替换本次日期，保留其他日期及未变更年级时间。停课和原本没有接送的日期不增加接送。
- 防重复应用、失败整体回滚、提交结果查询；模型失败记录可恢复查看。API 检查管理员身份、记录归属、来源及请求大小。
- 麦克风授权说明已加入 iPhone Info.plist；API 密钥、模型及可选价格表仅在服务端配置。

## 当前限制

- 已执行及用户锁定任务保持保护。未开始的既有临时线路可以再次调整；只替换选定日期，原范围内其他日期保留原名单、人车和时间，已生成的学生任务 ID、请假和历史保留。
- 搜索范围有限，不承诺全局最优或证明无解。没有实时路况和任务间转场耗时计算；保留原有站间时间的含义。
- 同站不同年级仍遵循现有最晚放学时间规则；保留同车方案时会说明等待情况，用户可以比较分批方案。
- 学生个人临时改时、任意新约束及班级筛选没有加入本版。模型应提示不支持，不能将这些请求静默扩大成整个年级变更。
- 推送、短信及司机已读确认没有新增。“已应用”表示数据库保存成功。
- 成本表缺失时记录真实返回用量，费用显示待核算；不虚报固定单次成本。语音单独记录原始用量。

## 配置与迁移

新增迁移 `023_rescheduling.sql` 创建调整请求和调用用量记录；`024_reschedule_replacements.sql` 记录临时线路替换来源，以便再次调整时保留学生任务历史。测试已在独立本机 PostgreSQL schema 执行全部迁移，没有对生产数据库迁移或写入。

服务端环境变量见 `.env.example`：

- `OPENAI_API_KEY`：API 密钥。
- `OPENAI_RESCHEDULING_MODEL`：支持 Structured Outputs 的模型标识，显式配置后启用入口操作。
- `OPENAI_TRANSCRIPTION_MODEL`：默认 `gpt-4o-mini-transcribe`。
- `OPENAI_PRICE_TABLE`：可选 JSON，以模型标识为键，记录每百万 token 的 `input`、`cachedInput`、`output` 美元价格，以及 `source`、`date`。按部署时核实的价格填写；推理 token 不重复计算。音频记录独立，当前不自动估价。

实际启用前需在目标环境执行迁移并配置上述密钥和模型。新增麦克风权限需要重新构建 App，纯 Web 更新不能代替原生权限声明。

接口依据：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[转写模型文档](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe)。没有在源码中硬编码文本模型或价格。

## 未配置 API 时的对话模拟

用户直接在 Codex 对话里说明日期、学校年级改时、不可用司机或车辆及要保留的线路。Codex 根据现有数据整理结构化 `intent`，运行同一个排班引擎，再反馈具体方案和冲突。这一步不依赖模型 API，不保存正式排班，也不验证未来模型的解析准确率。

- 纯虚构示例：`npm run reschedule:simulate -- --example`，无需数据库或 API。
- 真实数据：`node --env-file=.env.local --conditions=react-server --import tsx scripts/simulate-rescheduling.ts --input .local-data/adjustment-input.json`。连接始终在 `REPEATABLE READ READ ONLY` 事务中读取，最终回滚；不会创建草案、生成行程、写校历或执行迁移。
- 重放快照：`npm run reschedule:simulate -- --input .local-data/adjustment-input.json --snapshot .local-data/.../snapshot.json`，无需数据库，快照必须覆盖相同日期。

输入格式为 `{ "instruction": "原始指令", "intent": ... }`，`intent` 结构见 `src/lib/rescheduling/types.ts`。当前日期按洛杉矶运营时区校验。`--example` 使用固定的虚构日期，便于重复回归。

每次输出位于 Git 忽略的 `.local-data/rescheduling-simulations/`：原指令和条件、只读快照、候选 JSON、可读的 `report.md`。这些文件含学生姓名和路线信息，目录和文件限制为当前系统用户访问。正式应用仍需在已迁移环境通过原有确认流程执行；模拟命令没有正式保存功能。

## 每次调用用量与专用日志

每次模型调用在执行结果下方单独显示耗时、总 token、输入/输出 token、美元费用、模型、状态和记录时间，默认可见。缺失用量不记为零；费用按记录时的单价估算，保留六位小数。窄屏金额独占一行，避免被拆开。

持久日志复用项目数据库 `reschedule_usage`，每次追加条件、追问和失败调用均留存。新增 `npm run ai:usage-log -- --date YYYY-MM-DD` 只读导出 JSONL 到 Git 忽略目录，说明见 [AI 调用日志](ai-usage-log.md)。两次线上调用日志已导出核对；本地浏览器验证 320/390/1280px 显示、类型检查、Lint、构建和排班集成测试通过。
