# 同日车次共享接送名单

管理员在「今日运营 → 共享接送名单」选择两个尚未开始的车次和学校。两个车次须经过该学校及孩子的目的地；只共享该校当日已经安排的学生，其他学校名单保留原车次。两个司机不需要预先指定哪几个孩子坐哪辆车。

司机仍点现有的「已接到 / Picked up」。成功登记后，唯一的接送记录归到当前车次，保留学生、家长留言、请假和状态历史。另一端保留该孩子，置灰、排序到底部，显示接走的车辆；不能代替另一位司机撤销。原司机撤销接到后，两边恢复待接。送达后的撤销仍需先撤销送达，再撤销接到。

共享名单每两秒通过鉴权的只读接口更新，不触发日程生成。断网显示重试提示，不进行离线抢占。数据库事务串行裁决同时点击，第二次操作拒绝并刷新；不能产生两条接送事实。司机只能在本人车次登记和查看已授权的共享孩子照片，Test 照片替代规则继续生效。

容量按路线各区间检查，固定名单预留座位，共享名单只计算实际上车者。例如 12 座车固定接 Cherry Chase 5 人，则同车 Cumberland 最多登记 7 人。待接共享名单不等于本车乘客人数。完成车次仍需解决待接状态，不会把另一车孩子标记为本车送达。

共享设置属于所选当天车次。当前不自动建立 Little Tree 的两条线路、不自动复制到下一天，也不改动原固定名单；须先有两个已生成、可执行的车次。设置后普通固定线路生成保留该日共享安排，避免刷新时重置实际归属。共享设置不替代线路排班、放学时间与车辆可用性核对。

验证：本地独立 PostgreSQL schema 覆盖双连接同时抢同一孩子、越权、撤销后跨车重接、固定座位预留、送达撤销、照片共享权限及唯一记录／审计历史。类型检查、Lint、生产构建通过。未进行物理 iPhone 实机验收。
