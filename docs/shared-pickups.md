# 同日车次共享接送名单

管理员在「今日运营 → 共享接送名单」选择两个尚未开始的车次和学校。两个车次须经过该学校及孩子的目的地；只共享该校当日已经安排的学生，其他学校名单保留原车次。两个司机不需要预先指定哪几个孩子坐哪辆车。

司机仍点现有的「已接到 / Picked up」。成功登记后，唯一的接送记录归到当前车次，保留学生、家长留言、请假和状态历史。另一端保留该孩子，置灰、排序到底部，显示接走的车辆；不能代替另一位司机撤销。原司机撤销接到后，两边恢复待接。整体行程或所属线路分段完成后，不能再撤销或修改孩子状态。

共享名单每两秒通过鉴权的只读接口更新，不触发日程生成。断网显示重试提示，不进行离线抢占。数据库事务串行裁决同时点击，第二次操作拒绝并刷新；不能产生两条接送事实。司机只能在本人车次登记和查看已授权的共享孩子照片，Test 照片替代规则继续生效。

容量按路线各区间检查，固定名单预留座位，共享名单只计算实际上车者。例如 12 座车固定接 Cherry Chase 5 人，则同车 Cumberland 最多登记 7 人。待接共享名单不等于本车乘客人数。完成车次仍需解决待接状态，不会把另一车孩子标记为本车送达。

共享设置属于所选当天车次。当前不自动建立 Little Tree 的两条线路、不自动复制到下一天，也不改动原固定名单；须先有两个已生成、可执行的车次。设置后普通固定线路生成保留该日共享安排，避免刷新时重置实际归属。共享设置不替代线路排班、放学时间与车辆可用性核对。

验证：本地独立 PostgreSQL schema 覆盖双连接同时抢同一孩子、越权、撤销后跨车重接、固定座位预留、送达撤销、照片共享权限及唯一记录／审计历史。类型检查、Lint、生产构建通过。未进行物理 iPhone 实机验收。

## 固定线路共享（2026-09-09）

以上“仅当天车次”的限制已由本轮固定线路功能补齐。管理员在「线路 → 设置共享线路」选择名单主线路、另一条固定线路和共享学校，建立共享关系并在同一事务中启用两条线路。两线路须处于当前学期，起止日期、星期和共享学校接人时间一致，使用不同司机、不同车辆；当前支持两车、一个共享学校、一个共同下车地点，两条线路都须经过该地点。

共享学校的名单以主线路为准，另一条线路自动同步该校的学生和下车站映射，不提供另一份可独立编辑的共享名单。其他学校保留本车固定学生。新增学生的候选线路只提供共享主线路，避免添加到另一端后被同步覆盖。编辑任一线路时，启用状态、起止日期和星期同步到另一条；司机车辆及各自其他站点分别维护。需要调整共享接人时间时，先停用两条线路，分别修改一致后重新启用。

启用校验按每车区间预留固定学生座位，再合并两车可用于共享学生的剩余容量，不能把共享候选总数当成本车占座，也不能取消容量限制。每日生成仍应用学校日历、星期不接规则及当天请假；实际 Pickup 沿用共享抢占及单车容量校验。例如两辆 12 座车，主车固定接 5 人，则共享座位上限为主车 7 人、另一车 12 人。候选名单不预先分车，初始唯一记录归属不代表最终车辆。

任一司机读取当天任务均会在同一事务中处理共享组。重复读取不复制学生或车次；未开始的日期同步名单、司机车辆和站点，既有学生记录 ID 保持不变。两车任一侧已有上车、司机缺席、异常或完成事实时，整组保留当日安排；配置已变更时提示任务问题。移除带有状态历史的学生需人工核对，不丢弃审计记录。停用共享组取消未开始的车次，已执行车次保持原记录。自动同步遇到容量、资源或其他车次冲突时，取消该组未开始的已关联车次并记录问题，不能继续执行过期安排。

兼容已提前发布的独立共享车次：仅在两辆车、司机、日期、实际站点序列及当日学生集合均匹配，且仅两车共享、没有执行记录时自动关联固定线路。保留原车次及学生记录 ID；不按名称猜测或重复创建，不匹配时显示问题。已有执行记录的独立车次不自动关联。

迁移 `029_fixed_route_sharing.sql` 添加共享关系表及车次配置版本。学期归档快照包含共享配置；复制新学期时重建新线路之间的共享关系，线路仍为草稿、司机车辆待绑定，学生仍需学期核对。迁移已应用于当前数据库，未创建任何实际共享配置，也未自动启用 Little Tree 模板。

验证：本地隔离数据库全套 55 项测试通过；新增覆盖联合启用、容量拒绝、任一司机生成两车、主名单同步、ID 保留、旧车次关联、固定座位预留、跨车防重复、星期排除、失败取消/恢复、停用与已执行保护及跨学期复制。管理员真实表单提交在本机独立数据库通过，390px/1280px 无横向溢出；未进行 iPhone 原生实机验收，未提交、推送或部署应用代码。此前已发布的 Little Tree 周五车次未由本轮改写。
