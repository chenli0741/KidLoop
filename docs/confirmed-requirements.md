# KidLoop 已确认需求与实现边界

更新日期：2026-09-07。本文整理本轮用户确认的需求；当前实现以代码和 `PROJECT_OVERVIEW.md` 的实施记录为准。早期规划中的老师端、多组织协作等内容不代表已经上线。

## 核心流程

- 线路新增临时行程类型，开始和结束日期均包含当天，可设同一天；仍遵守星期、学校校历、学生不接送设置及既有冲突校验。结束日期次日（洛杉矶时区）从线路管理隐藏，历史执行记录保留，新学期不复制临时行程。原固定线路不受隐藏规则影响。
- 临时线路勾选原线路中的部分学生后，仅在适用日期替代这些学生的原安排，其余学生留在原线路。固定名单不改；临时停用、到期或无法执行时，恢复尚未开始的原安排。当天已开始的行程不自动移人，显示冲突供管理员处理；禁止两个临时行程在同一天争用同一学生，司机、车辆仍做冲突校验。

- 班级只保留为学生的可选文字资料，不再有添加班级或学校/班级对象选择；学校直接关联学生，已有班级文字和历史保留。新增、编辑、家长资料读取、司机名单和新学期核对统一使用学生班级字段。
- 学生可设置每周不接送（例如周二、周四），默认没有排除。自动日名单按学生星期设置排除，不自动标记普通缺席；清除设置恢复未开始日期安排，已执行/已明确完成的线路不重写。家长单日请假与学校特殊日期仍按各自规则处理；当前未新增单个孩子临时改日/改时的覆盖机制。

- 状态操作与页面加载解耦：Picked up、撤销、缺席、未接到及 Finish 在事务提交后返回当前行程的状态快照，仅更新本卡片的学生、进度及分段，不等待整页重载或自动生成线路；失败不显示成功。快照带执行版本，忽略迟到的旧结果。其他用户仍通过现有 30 秒刷新或重新进入读取数据库最新状态，不是实时推送。司机进入页面只生成本人当前绑定或当天已有任务关联的线路，仍检查跨线路冲突及司机改绑。管理员与家长保持原有范围。

- 状态更新性能：行程校历匹配、学生重复行程检查及名单写入按线路批量执行，不逐人往返数据库，保持原有事务锁、权限及已执行状态保护。第一轮批量优化的回滚诊断样本中，行程检查由 85 次查询约 3.8 秒降为 34 次约 1.5 秒；第二轮按司机限定范围的样本约 0.8 秒。第二轮本地浏览器使用临时测试行程，Picked up 点击至页面状态更新约 0.55 秒，仅一次 POST，无整页重载；这些结果不代表生产 iPhone App 的端到端保证。

**学校规则 → 固定多站线路 → 固定司机、车辆和学生 → 自动每日任务 → 状态记录。**

这是一套固定学期接送业务，不需要管理员每天安排司机、分配车辆或重新创建行程。线路规划和学校规则都是低频配置；日常主要查看任务、记录接送结果和处理变化。

## 学校规则与月历

- 特殊日期不等于放假：支持「全校同一时间」「按具体年级设置」「放假/不接送」三种安排。按年级时，每组选择具体年级和时间，同一天一个年级只能属于一组；未选年级继续每周时间，不引入低年级/高年级分类。临时时间不自动增加原本没有接送的星期。单日变更将起止日期设为同一天；迁移 020 保存分组，日历、预览与自动行程统一读取。

- Finish 仅在本线路所有学生为 Picked up、Dropped off、Absent 或未接到时可用；存在 Scheduled 时禁用并显示待处理数量，服务端事务内同样校验。撤销接到恢复 Scheduled 后，Finish 再次禁用，不得跳过接人直接送达。
- 「未接到」与普通缺席区分，是司机已通知家长自行安排后的最终结果，不是待解决的异常。沿用 EXCEPTION 存储值；预设原因依次为「临时接走」「孩子在学校但没有出来」「孩子被留校」「其他原因」。选择原因并确认已通知家长才能提交，原因和通知确认写入操作历史并在司机/管理员名单显示；只允许从 Scheduled 标记。Finish 保留未接到状态，不改成送达，计入已处理人数；家长事后请假也不覆盖该结果。此确认只是司机记录，不代表系统自动发送了通知。

- Picked up 学生也可撤销接到，恢复 Scheduled 并重新显示接到按钮；清除本次上车及送达时间、重算行程状态，保留状态操作历史，不影响其他学生。

- 学生不再单独操作 Drop off，统一由「完成本线路」送达。已送达学生提供撤销图标，恢复 Picked up，清除送达时间并保留原上车时间；同时撤销所属分段的完成记录、重算行程状态，其他学生及分段不变。已完成的整体行程也支持此纠错，已归档或取消的行程不允许修改，所有状态变化保留操作历史。

- 学校独立维护学期开始、结束日期，假期、不接送日期和特殊接送时间。用户确认所有当前学校本学期为 8/20–12/20，已按 2026 年设置 Ellis、McAuliffe、Stratford School，包含首尾日期；后续年份不自动推定。
- 接送时间按年级配置，不按班级配置。一条规则可多选年级，共用星期与时间，例如 1、2、3 年级周一至周五 14:30；某个星期时间不同则另设规则。
- 接送规则可用年级为 TK、K、1–7。已清理当前运营学期旧规则中残留的 8–12 年级；服务端保存和新学期沿用同样遵守此范围，存档历史不改写。
- 行程卡片按实际学生的「学校 → 课外班」组合分段显示，按上车站顺序排列，每段只列本段学生；连续执行的两段不再显示为四站共用一张混合名单。底层仍是同一行程、司机和车辆，学生任务 ID、状态操作及总进度不变。历史数据缺少上下车站关联时保留完整原名单，不丢弃学生。
- 分段线路全部在上方同时可见，不使用下拉框；每行左右两栏横向显示学校和课外班，各带时间，中间箭头。长名称换行，地图仅保留带提示的小图标，点击在 App 内打开。点击某行加深背景，下方仅显示其学生名单。
- 查看选择与实际执行指针独立：汽车图标始终指向第一条尚未明确完成的线路，不按当前时钟跳过前一条；查看后面的线路不会改变执行指针。「完成本线路」就是确认本线路全部 Drop off：按序点击并确认后，未完成且非缺席的学生统一标记为已送达，记录送达时间及逐人操作历史，不补造上车时间，已送达和缺席记录保持不变。完成后保存线路完成时间和操作者、重算整体行程状态，并自动切到下一条；重复提交不重复写历史。迁移 `018_trip_segment_completions.sql` 保存线路完成事实，生成器不得覆盖已明确完成的行程，学期归档包含完成记录。
- 每日行程以首个实际接送学校当天的年级规则或特殊时间为起点，早放学须提前，不能固定沿用模板的普通日时间。后续站点保留模板时间间隔且不得早于本站学生放学时间；同站不同年级采用最晚放学时间。已开始的实际行程不重写。2026-09-08 测试行程已更新为 McAuliffe 14:00、Ellis 12:45；模板同步采用周内最早时间作为基线，防止旧版服务重新生成时恢复旧时间。后续站点仍为测试行驶间隔，不代表核实过的路况或准点接送承诺。
- 班级仍用于学生资料和分组，不作为接送时间规则的配置粒度。
- 日历按月显示，可翻月、返回今天，标记假期、特殊时间、开学与学期结束、接送安排；点击日期查看明细。没有线路也能显示已设置的假期。
- 规则和日历按学校过滤。当前学校选择后自动切换，无需额外点“查看”。具体默认校历数据及来源见项目总览，不将测试时间当作学校官方时间。

## 固定线路

- `/routes` 是独立模块，不属于某所学校，也不受学校筛选影响。
- 线路由有序地点组成：学校 A → 学校 B → 课外班 C → 其他交接点。支持增删站点和调整顺序，不能限制为单一“学校到课外班”。
- 地点可选已有学校、课外班，或填写其他地点名称和地址。每站记录预计到达时间；学校已有接送规则可点击带入作为参考。
- 地址本身不能推导行车时间。当前没有地图路程耗时计算，站间时间由管理员规划；后台校验顺序与时间。
- 标题根据站点顺序自动简化生成，例如 `McAuliffe → One Stop → Stratford`，改变站点后同步更新；超过三个站点时以首尾概括，名称重复时自动编号。
- 线路配置起止日期、每周星期，绑定固定司机、车辆和学生，并指定每个学生的上车站及后续下车站。
- 可以先保存未启用线路；启用前必须具备有效学校规则、司机、车辆和学生。按每段实际乘车人数校验容量，检查司机、车辆和学生时间冲突。

## 自动任务与临时变化

- 保存线路时同步今天及已生成的未来任务；读取今天或未来某日时按需生成或同步该日任务，重复读取不会重复创建。当前不是定时批量预生成整学期。
- 学期外、放假或没有适用年级规则的学生不生成该日任务。多学校线路中一所学校放假，不影响其他正常上课学校的学生。
- “今天”展示固定安排产生的任务和执行状态。司机看到自己的线路、站点和学生；家长看到自己孩子的上下车地点、司机和状态。
- 原“当天调度”、每日“安排司机”和“创建行程”的操作流程已取消。旧入口跳转到固定线路。
- 临时换司机可直接修改线路绑定，作用于未开始和后续任务。这是持续变更，需要恢复时再修改；“只替换某一天”尚未实现，不是使用系统的前提。
- 已经发生司机操作的任务保留实际司机、站点和状态，不被后续线路编辑覆盖。历史行程保留。
- 无可用司机、车辆或存在当日冲突时，今日页提示管理员调整；不重复将同一学生安排到另一条有效行程。

## 学生接送状态

| 操作 | 含义 |
| --- | --- |
| 已接到 | 孩子已经上车；下一步可标记已送达、缺席或异常。 |
| 已送达 | 已完成送达。 |
| 人像 ×／缺席 | 未参与本次接送，或按用户确认用于已上车后由家长临时接走。保留原上车时间和状态历史。 |
| 红色三角／异常 | 标记异常；目前没有专门的异常原因填写流程。 |

已送达或缺席计入已处理人数。家长自行提交的请假与司机标记的缺席不同：家长不能用请假覆盖已经上车的事实；取消家长请假不会撤销司机手动缺席。不增加独立“已交家长”状态。

## 页面与账号

- Web 与 iPhone 使用两套布局，共享业务和权限。当前管理员手机导航为今日、学校、线路、学生、资料；“学校”模块的页内标签为“学校”和“日历”，分别维护学校规则和查看学校日历。
- 账号为管理员、司机、家长三种角色；系统账号管理放在 Web 后台，所有操作仍由服务端检查管理员权限。
- iPhone 右上角账号菜单包含当前账号信息、个人资料与密码修改、语言切换和退出；家长还可进入孩子资料编辑。
- 家长可查看已绑定孩子的信息、日程和当天状态，设置日期请假与特殊要求留言；不能修改孩子的学校、班级或课外班归属。
- 登录支持记住会话和邮箱提示，密码通过系统密码管理器自动填充，不在应用本地存储明文密码。账号密码不写入项目文档。
- 车队、学校、课外班资料统一在资料入口内管理。
- 学生页先按学校筛选，再显示学生列表；添加学生、班级用紧凑按钮打开弹窗，避免低频表单长期占用首屏。
- 接送点默认紧凑显示，长说明按需展开；有特殊要求保留提示，无示意图时不显示多余占位文字。多站行程按序显示站点，地址与地图可展开。
- 时间输入框限制在表单宽度内，处理 iPhone 输入控件越界问题。

## 学生照片

管理员添加或编辑学生、家长编辑孩子均可上传照片，支持预览和替换。Web 支持选文件、拖拽和粘贴，iPhone 支持相册及拍照。交互参考 RedHotWeb，但使用 KidLoop 自己的权限与私有存储。

浏览器先压缩图片，服务端再次校验、重编码、移除元数据；照片保存在私有 Vercel Blob，数据库保存受控引用。查看照片必须登录并具有学生访问权限。取消选图保留原照片，未关联上传暂作草稿；自动清理草稿尚未实现。原生相机插件或权限变化需要重新构建安装包。

## 新增学生自动安排线路（2026-09-08）

- 新增学生时，按所属学校和目标课外班，匹配当前工作学期内已启用、未到期的固定线路及有序上下车站点；不把临时线路、停用线路或已到期线路作为自动分配候选。
- 只有一个匹配方案时，保存学生自动加入线路。多条线路或同一线路有多组可行站点时，新增表单提供选择，不选则保留“待安排线路”；没有匹配线路也允许保存。切换课外班清空原线路选择。
- 服务端在事务锁内重新匹配，复用既有线路校验检查学校年级规则、司机车辆、站点顺序、容量和冲突。校验不通过时保留新学生及当前学期关联，回滚线路修改，并明确提示待安排原因；意外数据库错误仍回滚整个创建事务。
- 成功加入后同步今天及该线路已生成的未来日期任务，遵守假期、家长请假及学生每周不接送设置。已有执行事实的行程不自动加人，只影响未开始及后续任务。保存/读取触发机制不变，没有新增定时任务。
- 学生卡片对尚未加入有效固定线路的学生显示“待安排线路”，可进入线路管理继续安排。此功能用于新增流程，不自动批量调整既有学生的线路，也不改变家长权限或学生照片要求。
