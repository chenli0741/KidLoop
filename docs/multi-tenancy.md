# 独立机构运营与多租户

更新：2026-09-15。范围以本次用户确认及本文为准，取代此前的多组织协作设计建议。

## 已确认业务规则

- 机构仅指学生接送服务商。学校、课外班仍是机构内部的业务资料，不作为本期可协作的组织。
- 账号自行注册；注册和登录是全平台统一身份。注册后可创建机构，创建者成为该机构管理员。
- 用户通过机构代码申请加入，由机构管理员批准并指定管理员、司机或家长角色。机构也可按已注册邮箱直接绑定账号。
- 同一账号可绑定多个机构；司机资料、家长孩子授权、机构内姓名与联系方式均在各机构独立维护。
- 每次登录只选择一个机构：只有一个有效绑定时直接进入；多个时先选择。进入后不提供机构间直接切换，须退出并重新登录。
- 没有机构时可创建或申请加入。未登录页面提供“注册 / 创建机构 / 加入机构”入口，先注册或登录才能办理。
- 跨机构合作、共享学生或车辆、老师工作区、收费套餐、独立域名均不在本次范围。

## 实现状态与入口

代码及迁移已实现并在本地验证，尚未提交、推送、部署或应用到线上数据库。

| 入口 | 功能 |
| --- | --- |
| `/register` | 姓名、邮箱、密码自助注册；创建和加入入口提供对应说明 |
| `/login` | 统一登录；单机构自动进入，多机构进入选择页 |
| `/organizations` | 查看本人绑定、创建机构、按代码申请加入、查看审批状态 |
| 账号菜单 → 我的机构 | 当前机构名称、返回入口；当前会话不切换机构 |
| `/organizations` 管理员区域 | 机构改名、查看机构代码、审批或拒绝加入申请、指定角色和司机/孩子 |
| `/admin/accounts` | 绑定已注册账号、编辑本机构角色/关联、启用或停用本机构绑定 |
| `/profile` | 机构内个人资料；统一邮箱修改需验证密码，统一密码修改撤销所有机构登录会话 |

机构管理员不能重置共享账号密码或更改其登录邮箱，也不能停用其在其他机构的绑定。邮箱变更只能由本人验证当前密码后全局同步。邮箱相同、联系人姓名或手机号相同，不会自动授予孩子访问权限。

没有已绑定孩子的家长不会看到学生目录；管理员可以在审批时绑定孩子，也可随后在账号管理补充绑定。

## 数据和权限边界

`054_independent_tenants.sql` 建立首个机构“KidLoop 接送服务”，ID 为 `00000000-0000-4000-8000-000000000001`。现有业务行全部回填到这个机构，保留原 ID、关系、照片关联、实际时间、状态、定位与完成汇总。名称可以在机构设置修改。

- `login_accounts`：统一身份和密码。原账号 ID 和原密码散列迁入，密码无需重置。
- `app_users`：机构成员身份，保留原操作人 ID；新增 `account_id`、`tenant_id`。旧密码列只保留不可登录的占位符。
- `account_sessions`：全局登录会话，选定机构后不可改选；`user_sessions` 保留机构内会话撤销能力。
- `tenants`、`tenant_join_requests`、`tenant_audit`：机构、申请及审批/成员变更审计。
- `tenant_tables`：迁移时纳入隔离的业务表清单。今后新增业务表必须补充租户字段、策略、约束、运行角色权限及覆盖测试。

业务访问统一经过 `src/lib/db.ts`，从可信会话重查有效账号、成员、角色、司机与机构，再使用同一连接、同一事务执行。事务内切换为非表所有者、无超级用户/绕过行级安全权限的 `kidloop_runtime`；租户上下文事务结束后自动恢复。

数据库 RLS 同时限制查询和写入；组合外键防止跨租户关联学校、学生、司机、车辆、学期及操作人。业务运行角色无法读取全局密码与登录会话、无法重置成员密码或清空业务表。统计视图使用调用者权限，避免通过视图绕过 RLS。

只有身份和机构生命周期服务使用受控的高权限连接；业务模块不得直接导入此连接。身份服务的写操作必须使用登录身份及显式机构授权，不接受客户端身份声明。

每机构独立开放学期、车牌唯一性、地点用时、原因配置、线路、执行记录和统计。缓存通过隔离后的学期和租户策略划分；排班锁按机构划分。新机构只初始化通用缺席原因，不复制首个机构的学校、学生、司机、车辆或路程配置。

照片、头像、AI 调整和用量日志都在业务隔离范围内。文件路径包含机构，照片和头像读取仍须校验登录用户及角色。旧照片地址保留，由数据库元数据鉴权。

页面请求绑定渲染时的会话上下文，旧标签页会在会话改变时刷新；旧表单、Server Actions、写 API 的不匹配请求被拒绝。跨机构直接猜测记录 ID 仍由数据库隔离，客户端检查不是授权依据。

## 运维脚本

- 常规业务导入、试算、用量导出和接送重建脚本必须显式提供 `KIDLOOP_TENANT_ID`，通过 `kidloop_runtime` 执行；没有机构参数时拒绝运行。
- 原全局测试账号导入脚本已停用，应使用注册和机构绑定流程。
- 管理员启动脚本须显式指定机构。已存在统一账号时不会覆盖其密码。
- 数据库迁移与身份启动属于运维高权限路径，不得从普通业务请求调用。

- 本地 PostgreSQL 集成测试验证历史迁移、原密码和会话保留、逐表 RLS、照片隔离、跨机构外键拒绝、空机构初始化、独立学期/车牌/原因/路程、试算缓存、审批、角色关联、单次会话选机构、停用权限及全局改密撤销会话。
- 现有自动加开、生成幂等、已执行保护、逐人/批量送达和结束提取汇总回归通过；生成及接送操作额外使用运行角色测试。
- HTTP 验证：其他机构照片 ID 返回 404，匿名访问返回 401，旧会话或缺少机构上下文的写请求返回 409。新机构网页可正常创建独立学期。
- 实际数据只读快照在本地副本完成迁移：47 张原有表、863 条记录、5 个账号；迁移结果与源快照逐表比较，没有意外变更，原密码散列完整。备份及核对报告位于 Git 忽略的 `.local-data/multitenancy/`，线上数据未改动。
- 桌面浏览器验证注册、无机构引导、创建/改名、退出、多机构选择、申请加入与管理员批准。单机构账号直接进入家长端，未绑定孩子时显示空态，访问管理员页会返回家长端。修复了单机构登录重定向渲染被误判为旧表单的问题，补充会话请求边界测试。
- iPhone 17 Pro / iOS 26.4 模拟器安装独立 QA App，连接本地数据库；验证登录选机构、进入机构、账号菜单到“我的机构”、返回当前机构，全程保留在 App 容器。未进行物理 iPhone 验收。

## 上线切换要求

迁移与应用必须作为同一次切换发布：旧应用没有租户上下文，新数据库不能继续供旧应用写入。先备份、停止旧版本写入，确认迁移账号能创建/授予运行角色，再执行迁移并切换新版本；验证原账号、当前行程、照片和学期后恢复使用。不要先在线上单独应用 054，再继续运行旧代码。

现有登录会话迁移到首个机构；旧页面需要刷新以获取新会话上下文。第二机构产生数据后，不能直接回退到不带租户隔离的旧版本。若切换失败，保持停止写入并按备份和已验证恢复方案处理，不能重新生成真实历史行程作为回滚。

本次没有创建第二个线上机构。完成正式切换后，用户可通过网页自行创建，默认空白且与首个机构完全隔离。
