# 独立机构运营与多租户

更新：2026-09-16。范围以本次用户确认及本文为准，取代此前的多组织协作设计建议。

## 已确认业务规则

- 机构仅指学生接送服务商。学校、课外班仍是机构内部的业务资料，不作为本期可协作的组织。
- 公开注册仅用于新接送公司：负责人姓名、邮箱、密码及公司名称、电话、地址须完整填写，统一账号、公司与负责人管理成员在同一事务创建，任一步失败均不保留半成品账号。
- 其他公司工作人员、司机、家长均由公司通过邮件邀请加入，不公开注册、不按机构代码申请、不直接按邮箱绑定。工作人员使用现有 ADMIN 管理权限；司机关联公司已有司机名单，家长关联已有家长及孩子资料。
- 新受邀用户通过有效邀请设置密码激活；已有账号必须登录对应邮箱接受，只增加公司成员关系，不覆盖原密码。邀请链接 7 天有效，只能接受一次；重发使旧链接失效，公司可撤销。
- 同一账号可绑定多个机构；司机资料、家长孩子授权、机构内姓名与联系方式均在各机构独立维护。
- 每次登录只选择一个机构：只有一个有效绑定时直接进入；多个时先选择。进入后不提供机构间直接切换，须退出并重新登录。
- 未登录页面仅提供登录、注册公司入口。历史无公司账号须通过邀请加入；已登录账号不提供创建公司或申请加入入口。接受其他公司邀请不会切换当前已选公司的会话，进入新公司需退出后重新登录。
- 跨机构合作、共享学生或车辆、老师工作区、收费套餐、独立域名均不在本次范围。

| 入口 | 功能 |
| --- | --- |
| `/register` | 负责人账号与公司完整资料一次注册 |
| `/login` | 统一登录；单机构自动进入，多机构进入选择页 |

| `/organizations` 公司工作人员区域 | 编辑公司名称、联系人、联系邮箱、电话、地址；连接、更换或断开本公司 Gmail、查看发送记录 |
| `/admin/accounts` | 从名单邀请成员、重发或撤销邀请、查看最近 50 条邀请；编辑已加入成员、启用或停用绑定 |
| `/invite/[token]` | 新账号设置密码激活；已有账号登录后接受；打开页面本身不消费邀请 |
| `/profile` | 机构内个人资料；统一邮箱修改需验证密码，统一密码修改撤销所有机构登录会话 |

机构管理员不能重置共享账号密码或更改其登录邮箱，也不能停用其在其他机构的绑定。邮箱变更只能由本人验证当前密码后全局同步。邮箱相同、联系人姓名或手机号相同，不会自动授予孩子访问权限。

家长邀请保存发送时所选家长的有效孩子快照，接受时重新验证归属。孩子已移出该家长或失效则拒绝接受，应重新发送邀请；后来新增的孩子不自动授权，可在账号管理补充绑定。邮箱相同本身不授予权限。

## 数据和权限边界

`054_independent_tenants.sql` 建立首个机构“KidLoop 接送服务”，ID 为 `00000000-0000-4000-8000-000000000001`。现有业务行全部回填到这个机构，保留原 ID、关系、照片关联、实际时间、状态、定位与完成汇总。名称可以在机构设置修改。

- `login_accounts`：统一身份和密码。原账号 ID 和原密码散列迁入，密码无需重置。
- `app_users`：机构成员身份，保留原操作人 ID；新增 `account_id`、`tenant_id`。旧密码列只保留不可登录的占位符。
- `account_sessions`：全局登录会话，选定机构后不可改选；`user_sessions` 保留机构内会话撤销能力。
- `tenants`：机构及联系资料；`tenant_invitations`：邀请角色、名单关联、令牌摘要、状态与有效期；`tenant_audit`：机构与成员变更审计。旧 `tenant_join_requests` 只保留历史，新页面与 Server Actions 不再创建或审批申请。
- `tenant_tables`：迁移时纳入隔离的业务表清单。今后新增业务表必须补充租户字段、策略、约束、运行角色权限及覆盖测试。

业务访问统一经过 `src/lib/db.ts`，从可信会话重查有效账号、成员、角色、司机与机构，再使用同一连接、同一事务执行。事务内切换为非表所有者、无超级用户/绕过行级安全权限的 `kidloop_runtime`；租户上下文事务结束后自动恢复。

数据库 RLS 同时限制查询和写入；组合外键防止跨租户关联学校、学生、司机、车辆、学期及操作人。业务运行角色无法读取全局密码与登录会话、无法重置成员密码或清空业务表。统计视图使用调用者权限，避免通过视图绕过 RLS。

只有身份和机构生命周期服务使用受控的高权限连接；业务模块不得直接导入此连接。身份服务的写操作必须使用登录身份及显式机构授权，不接受客户端身份声明。

每机构独立开放学期、车牌唯一性、地点用时、原因配置、线路、执行记录和统计。缓存通过隔离后的学期和租户策略划分；排班锁按机构划分。新机构只初始化通用缺席原因，不复制首个机构的学校、学生、司机、车辆或路程配置。

照片、头像、AI 调整和用量日志都在业务隔离范围内。文件路径包含机构，照片和头像读取仍须校验登录用户及角色。旧照片地址保留，由数据库元数据鉴权。

页面请求绑定渲染时的会话上下文，旧标签页会在会话改变时刷新；旧表单、Server Actions、写 API 的不匹配请求被拒绝。跨机构直接猜测记录 ID 仍由数据库隔离，客户端检查不是授权依据。

## 056 原邮箱服务方案（历史实现，后续由 Gmail 替代）

本轮按用户要求不运行测试、类型检查、构建、浏览器或 iPhone 验收，也不发送真实邮件、不执行迁移。以下为代码行为与部署要求，不代表已验证或已上线。

- 新增 `056_company_invitations.sql`：公司联系资料、邀请记录及同一公司/邮箱最多一条待接受邀请的约束。原业务数据、账号密码及已有公司绑定保持原样；旧公司联系资料初始为空，由公司人员补齐。
- 邀请表仅供身份生命周期服务访问，业务运行角色无权读取。发送、重发、撤销先重查当前公司管理权限，接受时校验令牌、有效期、登录邮箱、公司状态及名单归属。
- 只保存随机令牌的摘要；明文令牌仅用于构造发给受邀人的邮件。邀请与携带邀请参数的登录页禁用 referrer。浏览邮件或邮件安全扫描 GET 请求不会激活账号。
- 邮件状态为 PREPARING → SENT/FAILED，接受变为 ACCEPTED，撤销或替换变为 REVOKED。SENT 只表示服务商接受发送请求，不表示实际收件箱送达；未知发送结果按失败处理，需人工重发新链接。不自动无限重试。
- 邮件发送在数据库事务提交后进行，不把外部请求放在数据库锁中。每公司每小时最多创建 100 条邀请；激活按 IP 限流。发送与撤销并发时，旧链接保持失效。
- 平台统一配置，所有公司共用邮件服务；本版接入 Resend API。各公司设置页仅显示配置是否齐全，不显示或修改平台密钥，不检查服务商连通性。

服务端环境变量示例见根目录 `.env.example`：

| 变量 | 内容 |
| --- | --- |
| `KIDLOOP_MAIL_PROVIDER` | `resend`，本版支持的发信服务 |
| `RESEND_API_KEY` | Resend 发信密钥，仅保存于服务端部署配置或本机未追踪环境文件 |
| `KIDLOOP_MAIL_FROM` | 经邮件服务商验证域名下的发件人，例如 `KidLoop <noreply@example.com>` |
| `KIDLOOP_APP_URL` | 正式系统 HTTPS 根网址，用于生成邀请链接，不带路径、查询或片段 |

启用步骤：准备发信服务账号并验证发件域名，将以上变量配置到应用服务端；备份数据库后执行 056，再发布依赖该表和字段的应用版本。缺少配置会阻止发送并提示；新增账号仍须公司资料完整才能注册。不要把密钥设为 `NEXT_PUBLIC_` 变量或提交到仓库。

本次未配置真实邮箱服务。邮件送达、完整注册/激活链路及 iPhone App 内跳转留待用户后续要求验收；本文的历史测试记录不可作为新流程验收证据。
